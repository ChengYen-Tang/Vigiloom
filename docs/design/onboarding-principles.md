# 設備、Agent 與服務的導入原則

REQ-05-T04 定義跨需求的一致導引；設備、安裝器及服務核准的實際畫面、平台能力與驗收分別由 REQ-07、18～20、22 和 25 交付。

## 設備與 Agent

1. Administrator 在 UI 新增設備時選擇「只監控 Ping」或「Ping ＋深入監控」，再輸入設備名稱、目標及群組。兩種模式都執行 Ping；深入模式不要求使用者知道所有 Agent 內部元件。
2. 預設 Private；選擇 Public 後才顯示公開名稱及範本選擇。變更公開範本與設定預設是範本管理操作，不因設備新增時間或範本是否預設而改變套用語意。
3. 深入監控接著提供與設備綁定的短效一次性註冊流程。依所選支援平台呈現可取得的正式簽章套件、版本、相容性、所需本機權限、中央出站 HTTPS 端點與明確步驟；只顯示實際驗證過的能力與安裝方式。
4. 安裝需要在目標主機執行及可能需要本機系統管理權；引導使用者或目標主機的管理者完成這次操作。Windows 可提供符合實際產物的圖形安裝流程；Linux 顯示可複製、可理解的安裝步驟。不可承諾所有環境都能免權限或零主機操作。
5. 註冊秘密只顯示一次，顯示到期與重發方式；不放入 URL、一般紀錄或可被其他使用者查看的命令列參數。傳遞及輸入方法由 REQ-18／20 驗證，不為方便犧牲憑證保護。
6. 安裝後 UI 持續顯示等待註冊、已連線、離線、設定待同步、套用失敗與各採集能力狀態；每種錯誤附具體可執行的下一步。Agent 失聯、Ping 不通和單項權限不足分開呈現。
7. 日常採集設定、版本指派及狀態在中央 UI 管理；更新／降版先驗證簽章與相容性，顯示進度和失敗回復，不要求使用者經常登入每台作業系統修改設定。

## 應用服務

1. 應用服務有自己的身分，不必綁設備或安裝主機 Agent。UI 提供 ASP.NET Core 等適用的 OpenTelemetry／Collector／Health Checks 接入指引及來源認證；安裝與設定內容以實際接收管線為準。
2. 待加入頁只顯示最近三分鐘仍有回報的未核准來源，以及名稱、必要來源識別和 `LastSeen`；持續回報就保留，停止超過窗口後離開候選視圖。候選名稱不是可信身分，來源認證與管理員核准分開。
3. Administrator 核准後才正式收集；核准前不呈現完整 telemetry 或捏造健康歷史。加入成功、等待首筆正式資料、來源被拒絕、資料過期與管線錯誤提供不同狀態及下一步。
4. 服務可自行設定 Public／Private；匿名頁只顯示允許的簡易服務狀態與歷史，詳細 Metrics／Logs／Traces 需登入授權。核准、公開與群組是不同操作。

## 各畫面實作時的檢查

- 為無資料、等待、成功、可復原錯誤與權限不足設計狀態；密碼、Token 和私鑰不能出現在一般讀取、日誌、截圖範例或公開頁。
- 桌面與窄螢幕均可完成主要任務；說明以產品語言描述，不要求使用者理解資料表、協定內部或容器拓樸。
- 安裝步驟、支援 OS／架構與本機權限以 .NET 10 官方支援及實際測試結果為準；未測能力顯示未知，不能宣稱已支援。
