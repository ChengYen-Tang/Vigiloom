# REQ-22 service discovery design work in progress

The Administrator uses this page to identify recent candidates, approve them as Private, and manage independently authenticated sources. It uses the [selected Vigiloom visual direction](Vigiloom-UI-Concept-2-Revision-2.png); the [exploration image](req-22-service-discovery-concept.png) contains fictional examples. Its source trust badges and implication that Private is administrator-only are not product behavior. The page explicitly states that the formal telemetry pipeline is not yet available.

The implementation presents source identifiers and requires a confirmation for approval and revocation, including when sources share a name. It shows a newly issued secret only in the issuance response; later reads do not include it. Source and candidate lists are paged independently. Other roles cannot access the management page.

Isolated SQL/HTTP tests cover two candidates and sources, one-time secret display, approval, revocation and authorization. Browser testing captured [desktop](evidence/req-22/desktop.png) and [390px](evidence/req-22/mobile.png), and exercised approval and keyboard focus in the mobile viewport. Both contain synthetic data only.

The [initial five-row comparison](evidence/req-22/comparison.png) exposed cramped columns and overly tall confirmation rows. The page was revised to use a compact table, non-wrapping environment and timestamp columns, and expandable confirmations and source identifiers. The [revised comparison](evidence/req-22/comparison-after.png) shows the result at a 1440 × 1024 viewport alongside the normalized concept. Both use five synthetic candidates, but row order, environments, time, session chrome and source status differ; the mock's fictional trust badges are intentionally not implemented. The source image is a general design direction, not an exact representation of the existing navigation or functional authorization model.

Typography and colors retain the existing application tokens (system fonts, dark-blue text, pale blue table headers); the table now follows the concept's column hierarchy. Confirmation and source IDs add necessary interaction and identity details. The concept uses icons which are not necessary for the real data; no source trust status has been invented. The mobile screenshot and interaction test cover no page-level horizontal overflow and keyboard expansion, confirmation and submission. Keyboard scrolling, screen-reader, error-state and concurrent expiry interaction checks remain outstanding; this comparison does not establish pixel fidelity or complete UI acceptance.
