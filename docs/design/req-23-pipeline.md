# REQ-23 pipeline reception design

The Administrator needs to distinguish authenticated source credentials, actual retained telemetry reception and Collector/application health. The [visual reference](req-23-pipeline-concept.png) uses synthetic data and the selected Vigiloom visual direction. It is not a claim that Collector heartbeat, automated configuration or application health already exist.

The reception overview shows the last persisted Log, Metric and Trace time per source. Empty values mean no retained matching records; a revoked credential does not erase history. The separate Collector health state remains unknown until a real health signal exists. The on-page guidance identifies the current OTLP/HTTP path and links to existing source management, but full Collector deployment and configuration remain unfinished.

Visual evidence uses an isolated LocalDB and synthetic source names. The [initial comparison](evidence/req-23/comparison.png) showed the source rows and guidance needed clearer hierarchy. The [first revision](evidence/req-23/comparison-after.png) made source identifiers compact and credential status more distinguishable. The [earlier comparison](evidence/req-23/comparison-final.png) adds a distinct endpoint block and credential safety panel. It compares the full 1487×1058 concept to a 1440px desktop full-page capture, scaled to a shared width; the reference's sidebar, example names, example URL and actions are not authoritative product features. [Mobile](evidence/req-23/mobile.png) is a 390px capture. The page was also inspected in the in-app browser; automated Chromium checks cover page overflow, the horizontal-scroll hint and keyboard focus on the table.

The page provides an authenticated download of the same two-source example exercised by the Collector interoperability test, plus setup and delivery-limit guidance. Source credential rotation is available on the source management page. The [final desktop comparison](evidence/req-23/template/comparison-contrast.png), [mobile view](evidence/req-23/template/mobile-contrast.png) and [expanded help](evidence/req-23/template/mobile-guide.png) show the guidance. The linked Collector reports page allows an Administrator to explicitly select a monitoring service, register a Collector and inspect per-instance uptime report times, while warning that this does not prove pipeline health. Administrators can manage source-to-exporter associations on a separate page; its [shared-style comparison](evidence/req-23/sources/comparison.png) and [390px view](evidence/req-23/sources/collector-sources-mobile.png) use test data. The example requires external configuration and the page makes that boundary clear.

The [Collector reports comparison](evidence/req-23/reports/comparison.png) places the selected pipeline concept next to the implemented reports page as a shared style comparison; the two are different screens, not a claim of identical content. The [390px view](evidence/req-23/reports/collector-reports-mobile.png) verifies that two services with the same display name remain distinguishable by their full identifiers. The browser test also checks the table's keyboard-operated horizontal scroll. The per-source counter page has separate desktop and mobile captures and a shared-style comparison; it is not a same-screen implementation of the reception concept. Per-signal comparisons do not establish overall pipeline health, which remains unknown.
