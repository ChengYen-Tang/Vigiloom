# REQ-07 設備管理設計

沿用使用者選定的 [第二輪第 2 張](Vigiloom-UI-Concept-2-Revision-2.png)：淺色背景、白色內容卡、藍色主要操作和清楚的設備狀態。此頁專注設備；應用服務仍是獨立維度。

- 清單以名稱、主要目標、監控模式、啟停及建立時間呈現設備，提供搜尋、排序、分頁與封存檢視。尚無實際監測結果時顯示未知，不虛構 Ping 數值。
- 管理員可新增與編輯；Read only 可查看設備但不顯示管理操作。表單保留輸入及逐欄錯誤；模式說明指出深入監控需要另外註冊 Agent，但不影響 Ping。
- Resources 模型的 `DeepMonitoring` 代表使用者選擇的能力模式，沿用骨架的 `HasAgent` 資料庫欄位以保留既有資料；此欄位不表示 Agent 已安裝、已註冊或在線。
- 主要目標與多個額外目標都支援 IPv4／IPv6／DNS；正規化後在同一設備內不得重複。不同設備的重複目標顯示提示並允許管理員確認，不能自動合併設備。
- 封存前明確說明停止監測及保留歷史；恢復保留設備識別並保持停用。名稱與目標修改保留原身分，歷史不改寫。
- 設備預設 Private。公開範本、匿名投影及與 Agent 的實際撤銷由 REQ-12／13 與 REQ-18 接入，不能把尚未交付的動作假裝成功。Ping 量測與實際狀態由 REQ-09 實作；群組由 REQ-08 擁有。
- 使用隔離的 LocalDB 與臨時測試帳號，在 in-app browser 實際走查清單、重複目標確認、新增設備、變更目標影響確認與 390 px 畫面。測試程序結束後已清理其資料庫。
