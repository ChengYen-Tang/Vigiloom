# Vigiloom 資訊架構與角色流程

此文件是 REQ-05-T01 的跨頁面導引。它描述完整產品的目標架構；實際頁面、資料與可用操作由各自的需求交付，不把尚未實作的連結畫成可操作功能，也不把本文件當作監控功能已完成。

## 主要入口

| 入口 | 匿名訪客 | Read only | Administrator | 所屬需求 |
|---|---|---|---|---|
| 公開狀態 | 僅明確公開的設備簡易 Ping 與服務簡易狀態／歷史 | 可瀏覽公開頁，也可登入工作區 | 可管理公開設定 | REQ-12～14 |
| 總覽 | 不讀取內部總覽 | 查看正式資源與異常摘要 | 同左，另有待處理管理工作 | REQ-10、24、37 |
| 設備 | 無內部設備 | 查詢全部正式設備，包括 Private 的進階資料 | 新增、編輯、群組、Ping 與 Agent 管理 | REQ-07～10、18～21、26～31 |
| 應用服務 | 僅公開服務的簡易狀態 | 查詢正式服務與進階證據 | 審核候選、管理服務與收集設定 | REQ-22～25 |
| 群組 | 僅公開投影允許的內容 | 查詢所有正式群組及成員 | 管理群組與成員 | REQ-08、12 |
| 網路測速 | 不因主選單存在而自動公開 | 查看已授權結果 | 執行測速與管理設定 | REQ-11 |
| 事件 | 不讀取內部證據 | 查看有權限的事件、狀態與證據 | 管理告警及通知 | REQ-15、37 |
| 設定 | 無 | 個人密碼與雙重驗證 | 帳號、API 憑證、通知、LINE、公開範本、Agent 與平台設定 | REQ-03、04、13、16、20、21、38、39 |

只有 Read only 與 Administrator 兩種人員帳號；匿名不是第三種角色。Read only 可讀所有正式設備與服務的登入後監控資料，包括 Private 和進階資料；密碼、Token、金鑰及管理專用入口不屬於一般監控資料。各入口在後端重新授權，UI 的隱藏或停用不是安全邊界。

## 主要旅程

1. **開始監控**：Administrator 建立第一位管理員並登入 → 選擇新增僅 Ping 設備或深入監控設備 → 填入名稱及目標 → 選 Private／Public；僅 Public 時才編輯公開範本 → 如需深入監控，依導引安裝及註冊 Agent → 看到 Ping、Agent 與能力的各自狀態。兩種設備都進行 Ping；Agent 安裝不等於 Ping 成功。
2. **加入應用服務**：Administrator 在待加入清單看到最近三分鐘仍回報的候選與最後回報時間 → 確認來源並加入 → 看到正式收集與健康狀態。未核准候選僅保留必要身分資訊，不顯示不存在的完整遙測。服務與設備維持不同身分；沒有可靠關聯時不強制指定主機。
3. **調查異常**：登入後從總覽的設備異常、服務異常或事件前往相應詳情 → 查看各自的狀態歷史、時間範圍與有權限的證據 → 返回事件或相關資源。設備 Ping、Agent 心跳、應用 Health Checks 與遙測不互相代替；缺資料不顯示成正常或零值。
4. **管理公開資訊**：Administrator 設定 Public／Private → Public 才能選擇公開範本與預覽可見欄位 → 確認後匿名頁僅顯示允許的簡易內容。公開名稱與內部名稱可以不同；IP、機密、進階主機／服務資料不因 Public 而自動公開。群組成員不改變公開權限。
5. **通知設定**：Administrator 從設定 → 通知 → LINE 管理憑證與接收目標、儲存並測試；結果在同一 UI 呈現。一般操作不要求登入外部監控後台或修改系統設定檔。

## 導覽與回饋

- 工作區導覽使用「總覽、設備、應用服務、群組、網路測速、事件、設定」；依登入狀態與角色顯示實際可用操作。未完成的目的地不提供假連結或假數值。
- 異常列表標識來源類型、嚴重性、目前狀態及更新時間，連到正確資源；群組可包含兩類成員，但各自分區、計數與狀態獨立。
- 所有需要等待的操作提供處理中與結果；空資料、未知、過期、失聯、未支援、無權限與錯誤互相區分，提供可理解的下一步。
- 進入個別需求時以 Product Design 設計該需求的桌面／窄螢幕與關鍵狀態；不以完成整站原型作開發前置。風格參考為使用者選定的 `Vigiloom-UI-Concept-2-Revision-2.png`，示範數據不作正式資料。
