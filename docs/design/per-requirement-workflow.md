# 逐需求 UI／UX 設計與驗證

REQ-05-T05 定義後續工作方式；它不把所有功能的原型提前做完，也不以尚未實作的操作或示範資料冒充產品能力。

1. 開始 UI 需求前同步現行需求卡、Task 和前置條件，閱讀 [資訊架構](information-architecture.md)、[共用視覺與狀態](visual-system.md)、[導入原則](onboarding-principles.md)及相關公開／授權規則。
2. 使用 Product Design 釐清本需求的使用者、目標、入口、資料與關鍵狀態；引用已選的第二輪第 2 張作風格依據。設備與服務分開建模，網路測速保有自己的入口；不重新要求使用者選整站視覺風格。
3. 為本需求需要的桌面與窄螢幕流程製作必要畫面或原型，包含載入、空白、錯誤、無權限及有影響的確認；涉及公開、安裝、服務核准或歷史時依各自需求補充狀態。原型使用明確標識的示範資料，不使用真實客戶機密。
4. 在已確定的架構和共用套件上實作 Blazor 頁面；共用元件或契約由單一擁有者整合，優先重用既有樣式與型別。瀏覽器元件只引用 Contracts，不引用 EF 或後端模組。
5. 以實際畫面及瀏覽器驗證必要工作流程、窄螢幕、鍵盤／焦點、文字替代與狀態；以 MSTest 驗證資料邊界、角色、匿名可見範圍及後端防護。UI 隱藏不取代 API 授權。
6. 將設計依據、可重現測試、限制與修正紀錄留在需求內，並交既有 Review Agent 審查。尚未交付的其他產品功能不以此工作流程標為完成。

公開頁不可顯示 IP、Private 資源、進階資料或機密；Read only 不提供管理操作；候選核准和秘密管理限 Administrator。以上為各 UI 需求都必須驗證的既定規則。
