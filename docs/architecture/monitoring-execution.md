# 監測執行位置與資源預算

REQ-06-T02 的工程規格；實際 Ping 採樣由 REQ-09 交付，測速執行與結果由 REQ-11 交付。此文件不宣稱這兩項已實作。共同預設以 ADR-0003 為準，所有時間以 UTC 持久化，顯示時使用 UI 選定時區。

## 設備 Ping

- 執行位置為中央 Worker 所在的網路命名空間；每個結果記錄該位置及實際量測時間。多個 Worker 共同服務同一中央監測位置，不各自對每台設備重複量測。不同網路位置及 Agent 探針不由本需求自行加入。
- 所有正式、啟用的設備均安排 Ping，包括未安裝 Agent 的設備；Agent 心跳及應用服務健康與 Ping 分開。新增設備時先排程，首次完成前為未量測；停用或刪除後不再排新工作。
- 預設每 30 秒、ICMP 每次一次、timeout 2 秒；管理員可調整間隔 10～3600 秒、timeout 1～10 秒，timeout 必須小於間隔。每設備依穩定識別分散起始時間，避免大量設備同秒量測。
- SQL 持久化每個設備的下一次到期時間與租約。Worker 有界掃描、原子取得租約並以代次防止過期執行者提交結果；同設備、同目標同時只接受一筆有效執行結果。Worker 當機可在租約過期後恢復。不能保證舊進程中已發出的封包被撤回，因此不宣稱物理封包絕不重疊。錯過的取樣不補造，下一次記實際量測時間。
- 預設每個 Worker 最多 64 個並行 Ping、可設定 1～256；平台部署者須按線路及多 Worker 總量調整，500 台只是目標規模，不作已量測的吞吐保證。不可為等待排程建立無界的每設備常駐 Task。
- 支援 IPv4、IPv6 與 DNS 名稱；IP 直接量測。DNS 每次執行解析一次，從解析結果選定一個地址並記錄實際地址與地址族；不可把多個地址任一成功當成所有地址皆成功。DNS 失敗、Worker 未執行或權限／網路例外是監測器錯誤或未知，不計成目標不可達。具體地址選擇與歷史可追溯規則由 REQ-09 定稿並實測。
- 只有完成的 ICMP 逾時或明確不可達納入失敗計數；預設連續 3 次失敗轉不可達、連續 2 次成功恢復。兩個門檻均可調整 1～10。未知、監測器失效、未量測及資料過期分別顯示，不當作成功或失敗；過期預設為超過兩個採樣間隔且不小於 90 秒。ICMP 被防火牆封鎖不能推論設備關機。

## 網路測速

- 唯一執行位置同樣是中央 Worker；結果呈現執行位置、外部測試端點、開始／結束時間、上下傳 Mbps、測試量及結果狀態。它代表中央位置到該端點的單一 TCP 路徑，不代表所有設備的連線速度。
- 選定 [M-Lab NDT7](https://www.measurementlab.net/tests/ndt/) 為第一個供應商：以官方 [Apache-2.0 參考客戶端](https://github.com/m-lab/ndt7-client-go) 和 [Locate v2](https://www.measurementlab.net/develop/locate-v2/) 整合；Windows／Linux Worker 發布需含相容且可驗證來源的客戶端，不要求使用者安裝 Go 或執行命令。REQ-11 必須釘選版本、驗證跨平台封裝與協定，並確認當時供應商政策仍適用。
- M-Lab 會永久公開測試結果及對外 IP，且通常無法移除；依其[隱私政策](https://www.measurementlab.net/privacy/)與[使用政策](https://www.measurementlab.net/aup/)，首次啟用或手動執行前，管理員須在 UI 看見資訊公開、流量、政策連結並明確同意。未同意時不得向 M-Lab 發出 Locate 或測試請求；撤銷後立即停止新測試，既有公開資料無法由 Vigiloom 刪除。商業整合及使用量可能有供應商額外條件，交付前需確認並記錄，不能代使用者承諾付費。
- 手動測速由 Administrator 操作；自動測速預設關閉，啟用時起始為每 6 小時、加隨機抖動，任意滾動 24 小時自動測試最多 4 次；手動與自動合計依目前供應商上限最多 40 次／24 小時，且共享每位置併發 1 的限制。多台 Worker 或重啟均共用 SQL 計數與租約；超限顯示下次可執行時間，不自動繞過限制。
- 預設每次上下傳合計 200 MiB 流量預算、最多 60 秒，並可由管理員設定更低的上限；每次計入已觀測流量及失敗／取消的消耗。達預算須停止讀寫並終止客戶端；已在途或系統緩衝的封包可能使實際網路流量略高，不能宣稱精確的線路位元組硬上限。官方 CLI 沒有現成的流量上限參數，REQ-11 須先驗證可即時量測及停止的適配方式，不能只憑事後結果假裝已限額。中止、預算耗盡及部分結果均清楚標示，不能當成完整成功測速；重試包含流量成本，不可無限自動重試。
- 不接受任意使用者輸入的測速 URL 作為目的地；端點由可信 Locate 回傳並依 REQ-11 做 TLS、主機與重新導向驗證。官方 CLI 在某些 CPU 預設會選明文 `ws`，整合時必須明確強制 `wss` 並驗證伺服器憑證，禁止 `-no-verify`。測速資料在 Vigiloom 內仍遵循既有私有／公開政策；第三方公開資料不受此設定控制。

## 工作排程與恢復

- Hangfire 1.8.25 的開源 Core／ASP.NET Core／SQL Server 套件集中版本；SQL framework 表使用獨立 `hangfire` schema。Worker 負責 Server，Web 不啟動 Server。日常畫面顯示狀態，原生 Dashboard 僅 Administrator，並驗證防偽及記錄變更操作。
- 分鐘級循環工作用 UTC 明確排程，時區與 DST 在設定時明示；預設跳過已過期的量測，不為遺漏時間補樣。通知與清理保留持久待辦並恢復；具體工作的重試政策不得假設第三方支援 exactly-once。
- 寫入來源交易與 Outbox 訊息必須同一 SQL 交易；訊息 ID 建立一次、重送不變。派送使用有界批次、租約與退避，完成持久化才確認；消費端以唯一鍵和原子狀態轉移實現冪等。外部服務逾時後結果不明時仍可能重複，應呈現診斷，不宣稱絕對一次。
- 工作有界重試、逾時、取消、最後錯誤與下一次嘗試；敏感憑證不放入工作參數或診斷。具體預設與可調範圍在 T01 實作前以工作類型定義，不能把所有工作強制套用同一組重試語意。
