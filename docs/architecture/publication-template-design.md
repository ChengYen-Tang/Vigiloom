# 公開範本與匿名投影設計

REQ-13 提供設備公開範本；服務及群組維持各自的公開設定。匿名資料仍必須符合 `public-data-contract.md` 的固定允許清單，範本只能縮小範圍。

## 管理與套用

- 範本是可獨立管理的資源，使用 UUID v7 Id、SQL `bigint` 叢集鍵及明確版本。名稱去除前後空白，非空且最多 256 字；有效範本名稱依資料庫的既有不區分大小寫名稱規則唯一。管理員可新增、修改、設定預設及刪除，後端驗證欄位與並行編輯。
- 公開顯示名稱和簡易狀態是基本資訊。可選的設備欄位限於延遲、觀測時間及契約容許的彙總歷史；IP、目標、Agent 及內部資訊不可選。歷史必須由真實公開歷史查詢交付後才能提供，不以開關假裝已可用。
- 設備選擇 Public 才可編輯範本選擇；尚無指定時預選目前預設，管理員仍須確認儲存。Private 設備不可由範本操作或預設變更而公開。
- 「設為預設」只變更未指定設備的預選，不重新指派既有設備。範本內容變更由同一規則即時作用於所有已選用設備，與是否預設無關。
- 修改或刪除前顯示變更的欄位、受影響設備數量及公開影響；預覽依據包含範本版本及所有受影響設備的穩定 Id／版本。預覽分頁顯示，後端以有界資源計算並重新核對影響集合，不將完整設備清單塞進瀏覽器請求；超出處理上限時明確拒絕，不截斷後聲稱預覽完整。提交時在一致鎖定下重新核對範本版本與影響集合，若任何項目已變更則要求重新預覽。
- 刪除採相同政策：預覽受影響設備，在用範本退休後，其設備公開投影停止，須由管理員明確重新指定；不得靜默切換預設。刪除目前預設且仍有其他有效範本時，管理員須同次選擇替代預設；刪除最後一個有效範本則清除預設標記。這只改變未來預選，不重新指派設備。

## 相容、安全與一致性

- 既有已明確套用 `baseline-v1` 的公開資源保留原政策，不因新增預設而重新指派；編輯器顯示這項既有選擇，不把它視為「尚未指定」而自動選取新的預設。裝置上的範本 Id 與固定 baseline 版本分開保存；未知、缺少或退休的範本不回退成較寬政策。
- 保存公開設定須核對設備版本、封存狀態和範本版本，並與稽核同交易。涉及範本、預設和設備選擇的管理操作使用一致鎖定順序。
- 匿名清單、單筆、搜尋、群組成員及計數使用同一有效政策判斷。多步查詢完成前重新確認設備版本、範本身分及版本／狀態；範本收緊或退休不能讓舊讀取回傳撤回欄位。匿名回應繼續採 `no-store`。
- 當設備由 Private 發布時記錄本次公開起點；範本退休後重新指定有效範本也開始新的公開期間。重新發布不開放先前 Private 或政策失效期間的歷史。既有 baseline 公開資源沒有可靠起點時採保守起點，不推定其過往均為公開。歷史顯示與查詢整合由 REQ-14 驗收；在真實歷史查詢交付前，管理介面與預覽明示歷史不可用，不提供無法履行的歷史選項。

## 介面

沿用既有 Vigiloom 藍白卡片、明確標籤及公開預覽。範本管理頁列出名稱、欄位、預設標記與使用數；編輯時先呈現影響與確認，再儲存。設備公開設定的 Public／Private 選擇仍在前，Public 時才顯示範本選擇及匿名預覽；Private 時只說明訪客不可見。空清單、載入失敗、版本衝突及無法預覽各有明確訊息；撤銷公開不依賴預覽成功。管理介面僅 Administrator 可寫入，後端再次授權。

## 交付順序

REQ-13 交付範本與有效匿名政策後，先回驗 REQ-08 的直接與群組查詢一致性。REQ-14 使用有效欄位、保留上限及公開起點實作真實公開頁／歷史；其頁面完成後再回驗 REQ-13 的公開頁整合，不要求任一方先整卡 Done。
