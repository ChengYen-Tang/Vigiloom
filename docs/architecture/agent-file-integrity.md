# Agent file and registry integrity

REQ-30 monitors administrator-selected scopes. A scope is an independently versioned file tree or Windows registry tree with its own root, exclusions, resource bounds and comparison policy. A scope revision identifies the effective policy; changing that policy starts a new baseline rather than interpreting the changed selection as file deletions. The first complete scan establishes a baseline and does not report every existing item as newly created.

The Agent reports observed metadata and cryptographic digests, not file contents or registry values. A difference reports what changed between two complete observations; it does not identify a user or process and is not a verdict that the change is malicious. A partial, inaccessible, interrupted, over-budget or inconsistent scan cannot replace a complete baseline or establish removals. Capacity, permissions, unsupported platform features and gaps must be visible to authenticated users.

Filesystem and registry notifications can request a bounded rescan. They do not constitute a reliable event log: an overflow, restart, disconnected watcher or unavailable native source produces an explicit coverage gap and a later reconciliation. Changes that appear and disappear between scans or during downtime are not recoverable from a snapshot. Reconciliation reports differences between observations rather than claiming all intermediate events were recorded.

The current Agent uses scheduled snapshots without continuous notifications, so every observation explicitly reports a coverage gap. The first complete observation is still a baseline; it is not a list of added objects. The Agent resumes an outstanding generation before collecting another and rotates across scopes when a collection is temporarily unavailable.

An observation's coverage-gap flag means changes may have been missed between the last reliable coverage and this scan. It is independent of scan completeness: a complete rescan can recover the current baseline while a gap remains in the intervening history. A partial result does not clear the gap. The gap and its scan progress must be durable across restart, queue failure and retries, and must not be cleared before a complete recovery generation is durably queued and centrally accepted. The first baseline is identified separately from a gap following established monitoring. All chunks of a generation must agree on the gap and partial-reason fields.

All paths, registry locations and metadata are private monitoring data. Configuration requires Administrator access, follows the existing Agent policy synchronization and owner binding, and is not part of public device projections. Scans share the cooperative Agent resource budget and durable queue limits. Symlink and reparse-point handling, exclusions, file and traversal limits, registry view selection, cancellation and denied access are bounded and reported rather than silently broadening scope.

The authenticated Agent identity owns each scope generation. Payloads and retry identifiers remain stable after enqueue; central receipt and changes commit atomically. Baseline publication requires a verified complete generation of the same scope and revision. Old revisions, retries, incomplete generations and identity changes cannot replace or delete a newer baseline. FIM data is exposed through the authenticated device details owned by REQ-31.

Retiring a scope prevents additional generations from being accepted. A bounded background cleanup closes obsolete staging and releases the retired scope's current baseline payload; the scope tombstone, closed-generation fence and recorded changes remain. A policy change similarly closes an obsolete in-flight scan instead of leaving another scope blocked until its staging timeout.
