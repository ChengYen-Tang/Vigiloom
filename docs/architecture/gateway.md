# Gateway routing and trusted proxies

The Gateway's `ReverseProxy` configuration controls destinations. The default Web, Agent, and OTLP routes all point to the existing Web host; configure their service endpoints separately as those services are extracted. The Gateway uses .NET service discovery: `Services:<name>:http` or `https` can list one or more endpoints, while deployments can also provide a resolvable service name.

When Web runs behind Gateway, configure `Vigiloom:Gateway:TrustedProxies` with the Gateway's connecting IP addresses. Web accepts the forwarded client IP, scheme, and host only from these addresses, before authentication and rate limiting. Without an explicit list Web does not process these headers. The local Development configuration trusts loopback for the local Gateway; production deployments must set the correct private addresses. Protect the network path between Gateway and Web and configure TLS and allowed public host names for the environment.

The Gateway routes existing traffic and applies authentication and authorization before forwarding. Integration with the extracted microservices remains in progress under REQ-42. Backend authorization remains in effect.

For the device and group APIs, Gateway applies the existing monitoring-read or device-write policy before forwarding. Account, Agent management, and settings API routes require an Administrator session. Other general API routes require a monitoring identity; Web continues to enforce the specific permissions for each operation. Public status and the LINE webhook remain accessible without a login, with the webhook validated by Web. Configure `Services:Identity:Url` to reach the identity service (a service-discovery name may be used). Gateway and Web must share the same Data Protection application name, key ring, and any key-protection certificate so Gateway can read Web login cookies. Cookie and API credential validation is performed against the identity service.

Agent requests use the Agent identity endpoint for Gateway authentication before forwarding; the Agent service still validates the request itself. `Vigiloom:Gateway:AgentIdentityAddress` optionally overrides the identity endpoint's service base address (default `http://vigiloom-agent`). Configure the Agent service to trust the Gateway's forwarding address when TLS terminates at Gateway. Enrollment, recovery, and credential rotation are forwarded to their existing dedicated validation endpoints.

OTLP and application discovery requests use the source identity endpoint on the observability service before forwarding. `Vigiloom:Gateway:SourceIdentityAddress` optionally overrides its base address (default `http://vigiloom-observability`). The internal `/internal/telemetry/source/identity` endpoint is not exposed by Gateway and must remain on the trusted service network. Configure the service to trust Gateway forwarding when TLS terminates at Gateway. OTLP authorization errors retain the existing protobuf error response format.
