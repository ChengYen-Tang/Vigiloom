# 設備、服務與 Agent 生命週期

狀態：REQ-02-T04 的設計基準。設備、應用服務與 Agent 各有獨立身分和狀態；本文件不表示功能、表或清理工作已實作。

## 設備

| 操作 | 行為 | 不隨操作改變的維度 |
|---|---|---|
| 新增 | 中央建立新的 UUID v7 DeviceId，建立時預設 Private；兩種監控模式均安排 Ping | 不自動註冊 Agent、核准服務或加入群組 |
| 名稱／IP／DNS 修改 | 保留 DeviceId；驗證後以新目標進行未來 Ping，歷史保留原發生時間及監測位置 | 不合併其他設備，也不因 IP 或主機名稱變更重新綁 Agent |
| 變更模式 | 同一 DeviceId；切到深入監控仍需註冊及驗證能力；切回僅 Ping 停用深入採集與顯示其狀態 | Ping 繼續；不自動刪除 Agent 身分或歷史，不改公開設定 |
| 停用 | 停止未來排程及深入採集，保留最後狀態與歷史並標示停用 | 不把停用顯示成健康；不自動刪除 Agent／服務或公開設定 |
| 封存／移除 | 管理員確認影響後，撤銷公開、停止排程、停用並撤銷對應 Agent 連線；從一般清單移至封存檢視 | 保留依政策可查的歷史及獨立服務，不 cascade 刪除其他資源 |
| 恢復 | 明確恢復同一封存資源及其 DeviceId；重新啟用所需監測或註冊，預設保持 Private | 不自動恢復已撤銷的機器憑證或原有公開權限 |

「移除」採可稽核封存，原始／彙總紀錄依各自 retention 清理；要重新建立一個不同資源就配置新的 DeviceId。名稱、位址或相同歷史不能作自動恢復依據。超出保存期的資料不因恢復而重現。最終硬刪及受到證據／稽核引用保護的處理需在 REQ-39 及所屬模組設計驗證；不得在本規格以 cascade 宣稱已實作。

### 目標格式與重複

- 允許 IPv4、IPv6 與 DNS 名稱；分別解析及正規化後儲存有效目標。DNS 名稱大小寫不構成不同名稱；IPv6 不同字面形式以解析後位址比對。不得從 DNS 回應自動改寫資源身分。
- 同一位址可對應多個明確建立的設備；UI 顯示重複提醒而非靜默合併，Administrator 仍可依實際監測目的建立。相同設備同一正規化目標不重複加入；多個目標屬同一 Device 的獨立監測目標，主要目標及每筆量測的實際位置須明確標記。
- DNS 解析失敗、ICMP 不可達與監測程序故障分開顯示。名稱／位址變更前預覽影響；不將 ping 失敗等同應用服務異常。

## 應用服務及執行個體

| 狀態／操作 | 處理 |
|---|---|
| 未加入候選 | 僅記錄識別候選所需的受信任來源範圍、FirstSeen、LastSeen；只有最近三分鐘仍回報者可見。只允許管理員讀取候選，不正式保存完整遙測 |
| 候選過期後再出現 | 原候選已不可見；再次出現建立新候選視窗，FirstSeen 從本次再出現重新計算。若保留內部清理記錄不得使清單顯示過期候選 |
| 管理員核准 | 以可信來源與穩定邏輯服務／環境識別建立 ServiceId，設定正式收集啟用時間；預設 Private。先核准後收集，不補入核准前完整 payload |
| 收集 | 合法來源的 instance 與外部 instance ID 維持獨立識別；可選、可信的部署關聯不要求綁定設備，也不繼承設備的權限或公開狀態 |
| 遲到資料 | 核准後才收到且已驗證來源的資料，可按來源事件時間保存並標示實際 ReceivedAt；事件時間早於核准時間者拒絕並計數，不補作核准前歷史 |
| 停收／撤銷來源 | 中央立即拒絕已撤銷來源的正式接收；顯示停收及資料過期，不把缺資料判定正常。保留 Public／Private 設定；已公開服務的匿名投影顯示停收／未知，不能沿用正常狀態。歷史依 retention 保留 |
| 封存／移除 | 管理員確認後停止收集、撤銷來源與公開，從一般清單移至封存檢視；保留政策允許的歷史。移除服務不刪設備或其他服務 |
| 恢復／重加 | 從封存恢復原 ServiceId 需管理員明確確認並重新授權來源，維持 Private；作為新服務加入時建立新 ServiceId。不能只憑相同名稱、IP 或 Collector 推定並自動合併 |

來源範圍、環境及實例去重的具體契約由 REQ-22／23 實作；不把 `service.instance.id` 直接轉換成資源 Guid。服務／instance 名稱變動不改已存在資源 ID，必須由已認證來源及管理流程決定是否屬同一資源。

每次核准／恢復收集建立新的授權期間及起始時間。中央只接受目前有效期間內所屬來源的資料，且 `OccurredAt` 不早於該期間起點；停收、撤銷及恢復前期間的遲到資料在恢復後仍拒絕並計數，不回補停收期間或舊授權期間。缺失來源時間依 ADR-0001 標示使用 ReceivedAt，不能偽造來源時間；時間偏移／可接受未來時間範圍由接收契約限定。

Instance 失聯時保留 Id、標示過期；當同一經認證的來源範圍與外部 instance ID 在有效授權期間再次出現，沿用未退役的 instance Id。管理員退役 instance 後不再自動復活；需明確恢復原 Id 或明確建立新 instance Id。無可信外部 instance ID 時不以 IP／名稱合併。instance 失聯或退役不自動停收整個服務。

## Agent 身分與重新綁定

| 情境 | 行為 |
|---|---|
| 首次註冊 | 管理員發放短效一次性註冊憑證；完成驗證後產生獨立 AgentId 與機器憑證，綁定已選 DeviceId |
| 正常重啟／升降版 | 持久化身分、設定、游標與離線批次；原 AgentId、MessageId、BatchId 與固定 payload 保持不變 |
| 重裝且原身分不可安全復原 | 管理員重新註冊產生新 AgentId 與憑證，舊身分撤銷；DeviceId 依管理員選擇保留，不以 IP 或 hostname 自動合併 |
| 複製機器／疑似重複使用憑證 | 不依主機名稱自動建立或轉移 Device 綁定；異常身分由管理員撤銷／重新註冊，保留可追查狀態 |
| 重新綁定 | 管理員明確選擇目標 Device 並確認影響。先完成舊 Agent 的待傳批次或明確確認放棄並記錄遺失數，再撤銷舊 Agent 憑證與綁定；以新 AgentId／憑證註冊至目標 Device，記錄新綁定生效時間。舊批次不可改 ProducerId、重包或歸給新設備；未上傳且已撤銷的資料不能冒用新身分補送 |
| 撤銷／失聯 | 中央立即拒絕已撤銷憑證；心跳失聯另行標示，不能視同撤銷或設備 Ping 不可達 |

## 發布、群組與可觀察性

- 設備／服務各自管理 Public／Private。只有 Public 設備能選擇公開範本；變更範本預設不重新指定現有選擇。切回 Private 後中央立即停止後續匿名輸出並處理快取／訂閱。
- 設備和服務可加入多個共用群組，同群組分區顯示；加入／移出群組不改發布、收集或資源狀態。刪除群組只移除歸屬，不刪設備、服務或歷史。
- 刪除／停收／Public 變更前呈現影響預覽及確認；每項狀態獨立儲存與稽核，避免一次操作隱性改其他維度。停用或封存若明確要求撤銷公開或來源，UI 必須在預覽中列明。
- 欄位級保留與清理由資料類別及 REQ-39 執行；管理操作失敗不得在 UI 顯示成功。Read only 可讀正式資源監控資料，但不能執行上述管理操作。
