# 公開資料與匿名查詢契約

此文件是 REQ-12 的欄位與權限基準；公開範本由 REQ-13 維護，公開狀態頁由 REQ-14 呈現。欄位允許不表示所有資源已經公開，也不表示相關 API 或 UI 已交付。

## 身分與範圍

| 資料或操作 | 匿名 | Read only | Administrator |
|---|---|---|---|
| 正式設備、服務監控資料 | 僅明確公開的資源及允許欄位 | 所有正式資源，包含 Private | 同 Read only |
| 原始 Ping、Agent、主機與遙測細節 | 不可取得 | 可依監控功能查詢 | 同 Read only |
| 機密憑證、來源金鑰 | 不可取得 | 不可取得 | 依各管理流程；不可從監控投影取得 |
| 變更資源、公開、範本、群組與設定 | 不可 | 不可 | 授權且驗證版本後可操作 |
| 候選服務及核准 | 不可 | 不可 | 可管理 |

帳號自行改密碼依既有帳號規則。群組不賦予或撤回設備／服務的可見權限，設備及服務各自決定是否公開，服務不要求綁定主機。資源新建或核准預設 Private，管理員可在獲授權的新增流程明確選擇並完成發布；既有資料移轉預設 Private。公有範本的預設標記與套用本身均不改變 Public／Private。

## 匿名欄位允許清單

匿名查詢必須在資料來源先限制可公開資源，再計算筆數、搜尋、排序、分頁和彙總；使用獨立的回應型別，不序列化登入後的設備或服務 DTO。未公開或已封存的資源以相同的不存在回應處理，知道 UUID 不繞過限制。錯誤、OpenAPI、記錄、匯出及推送也不能以另一條路徑透露私人內容。

| 對象 | 可允許的內容 | 不得公開 |
|---|---|---|
| 公開設備 Ping | 管理員確認的公開名稱、資源 UUID、簡化可達狀態、延遲與其觀測時間；可供範本限制的有界彙總歷史 | IP、DNS／目標、解析位址、監測位置、其他目標、Agent、OS、程序、軟體、資安與原始紀錄 |
| 公開服務 | 管理員確認的公開名稱、資源 UUID、簡化 Healthy／Degraded／Unhealthy／Unknown、狀態期間與有界彙總歷史 | 來源／instance 識別、內部環境與位址、健康檢查 URL／例外、指標細節、原始 Log／Trace、憑證 |
| 公開群組 | 經明確允許對外顯示的名稱，以及過濾後的公開設備與服務、數量 | Private 成員、含 Private 的計數與其他內部欄位 |

公開名稱可以預填設備名稱，但管理員發布前須確認其適合公開；服務名稱可能來自外部遙測來源，同樣須先由管理員確認。發布時保存經確認的公開名稱，後續內部名稱變動不會自動覆寫它；要變更公開名稱須再次確認。群組若選擇公開，也適用相同的獨立公開名稱規則。IP 不是可公開欄位；公開名稱的輸入與預覽須阻擋包含 IP 字面值的內容，包含嵌在其他文字中的位址；既有不符合規則的名稱不能直接發布。管理員仍需確認名稱及自行提供的文字不包含其他敏感資訊。

Ping 的 Unknown、待確認、監測失敗或過期不能顯示為成功；沒有成功樣本不能顯示為 0 ms。服務由健康檢查口徑計算，沒有足夠資料、過期或授權失效不可顯示為 Healthy，也不以 Ping 或 Collector 存活代替健康狀態。可用率由 REQ-24 的時間區間與涵蓋率口徑計算，不能把未知當正常；範本和公開頁不得推定不存在的事故或維護狀態。

公開歷史只提供經授權的彙總資料，時間為 UTC 並明示粒度；原始樣本、原始 Log／Trace 與內部目標不透過匿名歷史輸出。工程起始上限為 Ping 最近七天的五分鐘彙總、服務最近 90 天的每日狀態；範本可進一步縮小，不能擴大此上限。公開頁的日狀態、覆蓋率及時間切分必須使用 REQ-24 的真實區間與明定口徑，不以每日最後一筆假裝整日正常。REQ-13 提供已套用的有效範本版本，投影取其欄位／時間限制與本契約允許清單的交集；缺少、無效或不認得的版本一律不輸出該資源，不能回退成完整公開。預設標記只決定預選，不改變已套用範本或公開狀態。

為解除公開投影與多範本之間的交付循環，REQ-12 可提供具名、固定版本的安全基礎政策：只允許公開名稱、簡易狀態及設備 Ping 延遲，不公開歷史。管理員必須明確選擇 Public、確認名稱及該政策版本，預覽要清楚列出欄位與「目前不公開歷史」。這是已明確套用的有效政策，並非缺範本時的自動 fallback，也不會使 Private 自動公開。REQ-13 接入後使用同一有效政策契約，保留既有選擇，不靜默改用新的預設範本；多範本與公開歷史整合仍待實際交付驗收。

每次由 Private 發布為 Public 時，以該次發布提交時間為公開歷史起點；再次撤銷及重新發布後，只提供最新一段持續公開期間的資料。不能把發布前、Private 期間或跨邊界的整個五分鐘／每日桶直接顯示為公開：Ping 必須從起點之後完整的五分鐘桶開始，服務日狀態則以公開期間裁切真實狀態區間後計算。未公開期間不被當成正常或停機。若將來希望公開較早的歷史，需先設計明確預覽與授權，不能自行回填。

設備與服務的公開期間以保守的提交後時間界定：發布交易先寫入待確認標記，成功提交後才取 SQL Server UTC 時間，並以發布時的 rowversion 確認起點。確認失敗或版本已變更時保持待確認，匿名歷史不得輸出；以相同設定重試可重新確認。舊資料移轉採待確認而非假設過去已公開。公開起點本身不授權歷史，仍須有明確允許歷史的有效政策。

部署順序必須先排空所有舊版設備發布 writer，再執行重設 pending 的 migration，最後啟用新版 writer 與匿名歷史。既有資料庫約束無法辨認舊程式寫入的提交前時間；若舊 writer 在 migration 後又曾運作，必須重新將受影響起點設為 pending 並確認後才能啟用歷史，不支援混版期間開放匿名歷史。

## 撤銷、並行與快取

- Public 改 Private 或設備封存提交後，後續開始的匿名讀取不再返回該資源；設備恢復時維持 Private。變更與必要稽核在同一交易中成功或回滾。
- 服務停止收集、來源撤銷與取消公開是不同操作。停止收集或來源撤銷不能繼續沿用舊的 Healthy；其公開狀態依 REQ-24 的失效口徑顯示 Unknown。恢復收集不等於重新發布，Private 服務仍為 Private；若服務本來保持 Public，恢復後仍須等待有效的新健康證據。
- 查詢在伺服器重新檢查當前可見性，不能只靠瀏覽器隱藏欄位、先前清單或 UUID。多步驟讀取返回前須以目前已提交資料重新檢查可見性、資源世代與有效範本／政策版本，或以可靠的公開世代涵蓋其全部變更；不能在舊 snapshot 中重驗。與撤銷重疊、已經送出的 bytes 無法收回。
- 初版匿名回應採 `Cache-Control: no-store`，不使用可延後撤銷的應用快取；反向代理也不得快取此類回應。已送達訪客的資料無法回收。
- 若未來引入快取、匯出或即時訂閱，須在各傳送邊界重新驗證可見性，並證明撤銷後新查詢與後續推送不再揭露。沒有實作的匯出或訂閱不聲稱已受驗證。
- 公開設定變更使用資源既有 rowversion 做併發控制；舊版本不能覆蓋封存、撤銷或另一位管理員的變更。匿名與管理回應都不包含機密；例外回應不回傳 SQL 或內部位址。

此基準沿用現有 ASP.NET Core 授權、EF Core SQL Server 與資料庫交易，不新增僅提供相同基礎能力的套件。實作時參考 [ASP.NET Core 授權](https://learn.microsoft.com/aspnet/core/mvc/security/authorization/simple?view=aspnetcore-10.0)、[EF Core 併發衝突](https://learn.microsoft.com/en-us/ef/core/saving/concurrency) 與 [ASP.NET Core 回應快取](https://learn.microsoft.com/en-us/aspnet/core/performance/caching/middleware?view=aspnetcore-10.0)。

## 整合驗收

以真實資料驗證 Public／Private 混合清單、搜尋及群組計數，直接猜測 Private ID、封存／還原、Public→Private 與並發讀取；匿名／Read only／Administrator 及機器憑證分別驗證。對回應 JSON、HTML、標頭和錯誤執行負向檢查，確認 IP、私人名稱、內部目標與進階欄位均不洩漏。範本預選／變更與公開頁以 REQ-13／REQ-14 真實交付後整合驗收，不以本文件或模擬頁面標為完成。
