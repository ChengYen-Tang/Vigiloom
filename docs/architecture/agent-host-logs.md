# Agent host logs

REQ-29 is in progress. This document describes the intended implementation boundaries; it does not assert that a collector or an operating-system combination has been verified.

## Collection and durability

Windows Event Log, systemd journal and configured text files are independent sources. Each source has its own stable configuration identity and cursor. The Agent must not infer that an inaccessible source is empty or that the entire host is supported because one source works. Administrators configure enabled sources in Vigiloom; a source requires only the permissions actually needed to read it.

For each ordered source, commit the immutable serialized batches and the corresponding cursor advancement in the same SQLite transaction under the existing identity ownership and capacity checks. Compare the previous cursor and configuration generation so an obsolete reader cannot advance a reconfigured source. A source ID identifies the same native source; a different file path, channel or journal scope requires a new source ID. Configuration application must assign a fresh generation for each change and must never reuse an older generation, including after rollback. A generation change explicitly selects whether to preserve or reset its cursor, with resets reported as a possible collection gap. A full queue, failed commit or changed owner must leave the previous cursor effective. A retry following an uncertain outcome must inspect durable state rather than advance or recreate a new identity blindly. Only one producer may own a source; do not hold the identity lease while waiting on an operating-system source or the network. The sender retains existing acknowledgement, retry, quarantine and replay semantics.

Event bookmarks and journal cursors are opaque. Validate a resumed journal cursor against the actual entry: systemd may seek to a nearby entry when the exact one is no longer available. A missing or invalid bookmark, journal vacuum, cleared channel, file replacement, truncation, or unreadable source must surface a gap or uncertain completeness; do not report zero loss when its size cannot be known. A text-file cursor must distinguish file identity from path and account for partial encoded characters and multiline records. Bounds on event and batch sizes must be enforced before unbounded allocation; oversize and parse failures require visible accounting.

The Windows reader uses one local wevtapi query and event handle for bookmark, source identity and XML. It probes the required UTF-16 byte count before allocating the bounded application render buffer; oversized events return a candidate cursor that may advance only with a durable gap. For events within the limit, the cursor carries a digest of the complete XML. For oversized events, it instead uses a weaker fingerprint of bookmark, required size and bounded system creation time; it cannot prove that every channel clear or deliberately recreated identical metadata is detected. The bound applies to application render buffers, not all allocations inside Windows Event Log. Real Windows tests exercise bookmark resume and a deliberately small render limit, not a genuine huge event or actual channel clear. A self-contained x86 process also read and resumed the Application channel on this x64 Windows host; that does not establish coverage of every supported x86 OS. The current unelevated process was denied Security channel access, and the adapter reported it as unavailable; different accounts or event-log ACLs can produce different results. Elevated access, log clearing and retention races still need further platform tests and collector integration.

The initial Linux journal reader calls the local `libsystemd.so.0` journal API synchronously on one thread per handle. It checks the exact previous cursor before advancing; an unavailable cursor is reported rather than silently accepting a nearby entry. Journal fields are stored as an ordered JSON array of encoding/value pairs containing the complete `FIELD=value` bytes: UTF-8 text is preserved as text, and invalid UTF-8 as base64. Repeated field names and embedded newlines are preserved. When present and valid, `SYSLOG_IDENTIFIER`, `PRIORITY`, `_UID` and `_PID` are also projected as provider, level, user ID and process ID; missing or invalid fields remain unknown, and a journal event ID is not invented. `SYSLOG_IDENTIFIER` is source-supplied display data, not an authentication identity. Per-field and total-entry bounds apply, and a too-large entry returns a candidate cursor that requires a durable gap record before advancement. The systemd data threshold is only a decompression hint, not a hard native-memory cap. A successful read covers only journals visible to the Agent's account and selected local scope; it does not prove access to all system logs or namespaces. A self-contained Linux x64 probe read and resumed a Fedora 42 WSL journal with invariant globalization (the environment lacked ICU); vacuum, access denial, large compressed entries, and end-to-end queue integration still require verification.

The text-file byte reader identifies the opened file using Windows 128-bit file ID or Linux device/inode and any available creation time. It compares the previous 64 bytes at the cursor and checks file length on resume; this detects replacement, ordinary truncation, and many rewrites, but cannot guarantee detection of a rapid truncate-and-regrow or rewrite that recreates the same anchor. File IDs may also be reused. Gaps that cannot be proven absent must not be described as zero loss. The text source adapter re-reads and verifies the exact consumed prefix when the initial chunk contains more than one record; the candidate cursor covers only that prefix. A source on a filesystem that cannot provide the required identity must report unsupported rather than silently use a path as an ID.

The text adapter supports strict UTF-8 with either single-line records or indentation-based continuations. It preserves source newline characters and uses a five-second idle policy for incomplete trailing records; this uses filesystem modification time and wall clock, and does not prove that the source will never append a continuation. The 65,536-byte record limit includes newline bytes. Invalid encoding and oversized records return gap candidates that can advance only in the queue transaction. Oversized records without a known boundary are scanned in bounded chunks, with discard state and line-boundary state carried in the cursor. Several unknown-count gaps may describe progress through one oversized record; they are not a count of lost records. Tests cover source rotation, invalid UTF-8, cross-chunk multiline boundaries and queue restart. A real Agent host test collects a temporary two-line file and sends its records over validated TLS into SQL Server; sustained high-volume performance remains to be verified.

## Central admission and access

The authenticated Agent identity supplies the trusted source identity. The batch receipt, accepted log rows and existing shared `LogAdmission` token consumption must be committed atomically in the same SQL transaction. Check a previously accepted batch before consuming quota so acknowledgement loss and replay do not consume the budget twice. A quota refusal is retryable and must not acknowledge data. An already queued batch can exceed a subsequently reduced burst limit: retain it for diagnosis as a permanent rejection rather than retrying indefinitely or silently splitting it under new identifiers. Application and host records use the same central budget; they do not each get an independent global allowance.

Stored rows retain source and receipt timestamps, source identity, bounded original content and parsing metadata. Public projections must not expose raw host logs. Read access and source management are authorized on the server; collector permission errors and incomplete sources are visible without exposing credentials or arbitrary exception details.

The host-log batch contract represents collection gaps separately from source records: a gap has a reason and an optional positive affected-record count, with null meaning unknown. It cannot simultaneously carry event content or event metadata. Gap message IDs share normal deduplication, admission and receipt semantics; a retry cannot change the reason or count under the same message ID. The local queue can commit such a batch and a new cursor atomically. SQL retains the gap fields and refuses to downgrade the migration when gaps exist. An authenticated monitoring API queries records and gaps by bounded central receipt-time range and keyset page, retaining source time as a separate nullable value; a real TLS Agent test verifies that received text records are queryable. Keyset pagination follows current data and is not a fixed snapshot during concurrent inserts or retention cleanup. SQL Server tests verify the receipt-time source index exists; query execution plans and production-scale performance have not been measured. The cross-source query UI remains owned by REQ-31 and REQ-37.

The native-source adapters translate a missing bookmark or journal cursor into an unknown-count gap and a durable restart marker. Only after that gap and marker are queued does the next read begin at the first available entry, so recovery does not skip that entry. A source may retain entries that were already collected, so this recovery can generate new records for earlier events; the transport's batch deduplication does not make source recovery exactly once. Oversized native events become a known one-record gap with their candidate cursor. Adapters are wired to the hosted collector.

The collection-cycle primitive rotates its starting source and bounds work per source; a full local queue stops the pass without advancing the refused cursor. It checks that settings are still current after each source read; at queue commit it also checks the identity-bound saved-settings token and source generation while holding the same identity lease used by settings saves. Thus a new saved snapshot fences an older read, even if the in-memory change signal is late. The hosted worker supplies the saved token and holds an exclusive log producer lease until collection stops. An unsupported or unreadable source returns a diagnostic status without inventing a cursor or repeatedly fabricating loss records.

Metric and log collection share one cooperative CPU, working-set and process I/O budget, and serialize sampling while accounting for their work. A limit can defer a later sampling cycle; it is not an operating-system hard limit and an individual operation can exceed it. There is no network bandwidth quota. Process I/O counters may nevertheless include other process activity, depending on the platform. Sending queued batches is outside this sampling gate.

The collector aggregates records for one source into a bounded batch, and commits the batch with its final cursor. Its periodically synchronized batch-count limit is the smaller of the central source burst, global burst and protocol maximum; a quota change alters the snapshot revision. When a batch reaches a bound it yields before another bounded pass; resource thresholds and a full queue still defer collection. A quota reduction can still reject batches produced before the Agent next synchronizes. Source records not yet read remain subject to native log rotation and are not protected by the Agent queue. An isolated Windows integration test appends 100 records in ten bursts while the hosted Agent sends through validated TLS to SQL Server and verifies their order, using an advanced test clock. This short scenario is not a production-scale sustained-rate or resource-use benchmark.

The unreleased development prototype used an incompatible source-settings cache before the batch limit was added. For that prototype only, stop the Agent and remove `log-settings.dat` from its state directory; the next successful synchronization downloads the current settings. Do not remove identity, the queue database or cursor data. This is not an upgrade procedure for released versions.

Desired source snapshots have a bounded number of immutable source settings and a canonical revision. Source identity fixes native kind and target; updating other settings generates a fresh UUIDv7 generation, while retirement retains the source row as a tombstone. A rowversion detects concurrent edits. EF migrations refuse to drop populated source settings. Adjacent snapshots also check identity and generation consistency. Authenticated settings APIs and the administrator management UI are available.

The Agent reports bounded per-source observations in its ordered heartbeat, including the observed settings revision and each source's generation and monotonic observation age. It does not report paths, event content or exception details. The platform accepts only the current heartbeat session and sequence; the management page matches the active desired revision and source generation and labels old or absent observations as unknown. A queued record is not proof of central receipt; an empty source is not proof of complete visibility. The report also distinguishes sampling deferred by resource thresholds. The management page has been compared with the selected visual direction on desktop, and its narrow layout and a form focus transition were checked; this is not a complete keyboard or screen-reader audit.

The configuration application service creates, updates and retires per-device sources, authenticates Agent snapshot requests, enforces the active-source limit under a serializable transaction, and saves change metadata in the same transaction. The administrator audit page and API expose actor, device, source ID, action, timestamp, generation, enabled status and row version; they do not contain the old and new name or text mode. Administrator API writes require browser-session authorization and antiforgery; an Agent can fetch only its own snapshot, and credential revocation is checked before responding to conditional requests. The Agent restores its identity-bound last-good cache and synchronizes it on the existing settings schedule. A saved snapshot is desired configuration, not evidence of application. An unauthorized result suppresses the snapshot in the current runtime until a successful sync; this suppression is not persisted across process restarts, and central reception always checks current authorization. SQL integration tests start concurrent creates at the final source slot and exercise snapshot delivery around retirement and credential revocation commits under normal and snapshot reads. The tests do not instrument the exact SQL lock acquisition point.

## Compatibility and acceptance

Introduce a distinct versioned Agent batch schema. Upgrade and drain all central receiver instances before enabling host Log collection: older receivers do not check Log message IDs when accepting other batch types. An Agent must not quarantine valid new-schema data merely because an older platform does not advertise that schema. Queue-format changes must make incompatible downgrade behavior explicit, including older senders that would classify an unknown batch schema as invalid even if they can open the database. Validate actual crash/restart, full queue, ambiguous commit, event loss, file rotation, permissions, retry/deduplication and shared host/application quota. Platform support is limited to combinations actually exercised; Linux journal availability and Windows Security Log permissions depend on the host configuration.
