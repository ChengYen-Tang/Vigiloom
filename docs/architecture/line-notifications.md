# LINE notification integration

Vigiloom uses the [LINE Messaging API](https://developers.line.biz/en/docs/messaging-api/), not the discontinued LINE Notify service. An administrator configures a channel access token and channel secret in the settings page. Enable webhook and allow the LINE Official Account to join group chats in the LINE Developers Console, configure the HTTPS webhook URL shown by Vigiloom, and invite the account to the group. Webhook events only discover a candidate; an administrator must approve it in Vigiloom before it receives notifications. LINE group identities are separate from device groups.

Webhook signature verification and event decoding use the community-maintained [`Line.OpenApi.Messaging.Webhook` 1.1.0](https://github.com/pierre3/line-openapi-dotnet), MIT licensed and targeting .NET 10. The package implements LINE's [raw-body HMAC-SHA256 signature procedure](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/). Push messages use the [official LINE HTTP API](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/) through pooled `HttpClient`; each delivery uses a stable retry key and immutable recipient and content. LINE acceptance does not prove delivery or reading, and LINE only honors the retry key for 24 hours.

Web and Worker must share the configured ASP.NET Core Data Protection key ring to decrypt the same channel credentials. The normal UI, API and logs do not return credentials. The deployment must expose the webhook over HTTPS to LINE; an inaccessible local-only endpoint cannot receive group events.
